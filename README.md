# FPSWatcher Next

FPSWatcher Next is a rootless-first Android performance monitor rebuilt with a Flutter interface, a Rust parsing/export core, and an Android Kotlin platform layer.

## Access modes

- **Standard:** no root and no Shizuku. Shows every metric exposed through normal Android APIs or readable proc/sysfs files: CPU usage/frequency when available, RAM, battery and power, Android thermal status, refresh rate, network throughput, storage, foreground package through Usage Access, and the GPU renderer through EGL.
- **Shizuku:** runs a small UserService with Shizuku's privileged identity. Adds SurfaceFlinger frame statistics and attempts otherwise restricted CPU, game-process RAM/CPU, SoC thermal, GPU frequency, and GPU load reads without requiring root.
- **Root:** uses `su -c` as the widest privileged fallback.
- **Auto:** prefers Shizuku, then Standard mode. It never invokes root automatically.

Android vendors expose different sysfs nodes and restrict them differently. GPU load/frequency therefore remains device-dependent even with Shizuku. GPU model detection through EGL does not require root.

## Main features

- Live FPS, P90, P99, frame time, and frame-count parsing from SurfaceFlinger timestats.
- CPU, GPU, foreground-game CPU/RAM, system RAM, battery, SoC thermal, refresh-rate, network, and storage cards.
- Draggable compact in-game overlay.
- Native foreground session recorder that keeps collecting while the game is in front and the Flutter screen is not visible.
- Up to six hours of one-sample-per-second session history, mirrored to private app storage so a killed UI process does not erase the latest recording.
- Dashboard PNG export through Android's system file picker.
- Full CSV export generated by the Rust core, with a Dart fallback if the native library is unavailable.
- Completely redesigned dark Material 3 dashboard and a new adaptive application icon.

## Build on Windows

1. Install Flutter, Android Studio/SDK, Rust, and Git.
2. Open PowerShell in the repository.
3. Run:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
./tool/bootstrap_android.ps1
./tool/build_rust.ps1
flutter pub get
dart run flutter_launcher_icons
flutter build apk --debug
```

The debug APK is created under `build/app/outputs/flutter-apk/`.

## GitHub Actions

Pushing the repository triggers `.github/workflows/android.yml`. The workflow generates the Android host project, builds the Rust libraries for common Android ABIs, analyzes and tests the project, builds debug and release APKs, and uploads them as artifacts.

## Android access

- Usage Access identifies the foreground game.
- Display over other apps enables the floating overlay.
- Notification permission is recommended on Android 13+ so the foreground monitor notification remains visible.
- Shizuku permission is optional and requested only by the user.
- Root is never used in Auto mode and must be selected explicitly.

## Legacy APK inspection

The supplied v0.3.0 APK was a small Java-only application using `UsageStatsManager`, a native overlay service, `/proc/stat`, CPU sysfs nodes, battery APIs, and root shell commands. It did not contain Flutter, Rust, Shizuku UserService integration, or session export support. See `docs/legacy_apk_report.md`.
